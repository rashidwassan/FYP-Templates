How it works

From template to your FYP in four steps

01

Pick a problem you care about

Browse the cards or the ideas backlog. The best FYPs come from a problem you have seen yourself.

02

Open index.html

No install, no build. Everything runs in the browser and saves to localStorage. Serve over HTTP for camera, GPS or notifications.

03

Read the README and the code

Each README explains the problem, the architecture of the file, and the domain logic. The code is commented at the seams.

04

Build what is left for you

Search for TODO(student). Backends, authentication, ML models, maps and notifications are intentionally unbuilt.

Single file. Vanilla JS, inline CSS, SVG charts. Lazily loaded libraries only where unavoidable.
Local-first. Namespaced localStorage with realistic seed data, export and import.
Bilingual. English with an Urdu toggle wherever the audience is the public.
Distinct design. Different palette, type and layout per project, proper icons, fluid motion.
Extension points. TODO(student) markers, an About panel and a README table in every project.
One PR per project. Each template lands from its own branch into main.
